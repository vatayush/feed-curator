Feed Curator · how it works

Inside Feed Curator

Twice a day a Chrome extension reads your X feed in your own browser. Claude Code scores every post against what you've told it you want, and you read the few that matter on a private page on claude.ai. This page walks through each part, where your preferences live, and which part of the system reads them.

Stage 1

Capture: reading X in your browser

The extension schedules itself with Chrome alarms, by default at 07:45 and 17:45 local time. You can change the times in its popup. At each time it:

  • opens x.com/home in an inactive background tab, using the plain feed URL with nothing added that a site could notice
  • reads the Following tab, then For you, each until 60 posts, 90 seconds, or six scrolls in a row with nothing new
  • skips ads and promoted posts, notes which feed each post came from, and saves a post seen in both feeds once
  • closes the tab, and leaves X on whichever tab you had open
  • sends the run to the capture helper over Chrome's native messaging. The helper writes captures/x-<time>.json and x-latest.json and keeps 30 days.

A run more than an hour late (for example, the Mac was asleep) is skipped instead of firing at an odd hour. LinkedIn works the same way, three minutes after X, but is off by default.

On X, sort Following by Recent. Sorted by Popular it shows only a handful of posts, and the popup will say so.
Stage 2a

Starting curation without you

When a capture has posts and autoCurate is on in config.json, the helper starts curation. macOS doesn't let Chrome, or anything it runs, open documents in Terminal, so the helper asks launchd to start a small on-demand job instead. The job has no schedule; its only action is to open curate/curate.command in Terminal.

Curation runs as an interactive Claude Code session because the tool that reads and writes the page's database, ArtifactData, is available there. It uses your Claude subscription; there's no API key. The session ends itself once Claude has written its one-line report, or after 15 minutes at the latest if something gets stuck.

Stage 2b

One curation run

  1. Export the page's data

    Claude lists each collection on your page (prefs, people, keywords, votes, settings, digest) into a fresh work/run-<time>/db folder.

  2. Prepare

    prepare.py merges the latest captures with that data. It applies the hard rules itself, so they behave the same every time, and writes judge.json (what Claude scores) and state.json (everything else). It stops early if the newest capture is more than 3 hours old or was already curated.

  3. Judge

    Claude reads judge.json and writes scores.json: for every post, a score from 0 to 1, a one-line reason, and a topic.

  4. Apply

    apply.py checks there's exactly one valid score per post, merges in the rule decisions, and builds digest.json, trimming long texts to fit the page's 256 KB document limit.

  5. Publish and report

    Claude writes the digest to digest/current on your page, pinned to the version it read so it never overwrites a newer one, and reports something like “X captured 7:45 AM: 119 read · 14 kept · 105 dropped”.

How Claude weighs them

Preferences come first, then votes. Posts from the Following feed win ties, because those are people you chose, but a meaningless reply from someone you follow still scores low. Replies that mean little on their own, engagement bait and unrelated topics land under 0.3. Image-only posts are judged by author and context, and rarely above 0.5. The full rubric is in curate/CURATION.md, which you can edit like any other file.

Applying changes right away

Strictness changes take effect immediately. Other changes apply at the next capture. To apply them now, open Claude Code in the Feed Curator folder and ask it to re-curate; it runs prepare.py --force on the same capture.

How long a vote lasts

A vote never expires on a timer. It lasts until newer votes push it out, and it counts in two ways for different lengths of time:

How the vote is usedWhich votes countAt about 10 votes a day
Similar posts move up or downYour latest 100. Claude sees each vote's first 200 characters, author, feed and topic.about 10 days
The author's standingAll stored votes, up to 500, tallied as 👍 and 👎 per authorabout 7 weeks

The page stores your 500 most recent votes. Once you have more, it deletes the oldest the next time you open it. If you vote less often, each vote lasts longer.

  • Undo: tap the same 👍 or 👎 again and the vote is deleted.
  • Switch: tap the other button and it replaces the old vote.
  • Start over: the Your data section on the Preferences tab downloads everything or resets it.

Like preferences, a vote counts from the next curation run. It doesn't change scores already on the page.

Claude pieces

Skills, tools and hooks

skill · .claude/skills/curate

/curate

Runs one curation pass by following curate/CURATION.md step by step. Started automatically after a capture, or by typing /curate yourself.

skill · .claude/skills/setup-page

/setup-page

Run once by the installer. Publishes artifact/feed-curator.html as your own private page, with a database and file downloads, and saves its link in config.json.

tool · ArtifactData

Page database

Reads your settings and votes (list, get, query) and writes the digest (set on digest/current, pinned with if_version).

tool · Artifact

The page itself

A single HTML page on claude.ai that renders the digest and settings live from its database. It works in the Claude app on your phone.

hook · PreToolUse · curate/guard_artifact.py

Guard

Checks every ArtifactData call. It allows reads of your own page and writes to its digest only, and blocks everything else, including other artifacts.

hook · Stop · curate/end_auto_run.py

Clean exit

Ends an automatic session once Claude has finished, so its Terminal window closes. Sessions you open yourself are left alone.

permissions · .claude/settings.json

Pre-approved steps

An unattended run can run date, prepare.py and apply.py, read the project, and write in work/. Anything else stops at a permission prompt.

rubric · curate/CURATION.md

Instructions

The exact steps, the scoring bands, and how to write reasons and pick topics. Edit it to change how Claude judges.

Safety

What keeps it careful

  • Read-only on X. It never posts, likes, follows or replies. It reads at most twice a day, scrolling slowly, for at most 90 seconds per feed.
  • Safety stops. A login, captcha, logged-out, rate-limit or security-check page stops the run at once, leaves the tab open for you to see, and pauses that site for 48 hours. Pressing Run now in the popup clears the pause.
  • Posts are data, not instructions. Posts are written by strangers and could try to talk Claude into something. The skill tells Claude to judge them, never follow them, and the guard hook limits what any run can touch to your page's digest.
  • Private by default. Captures stay in captures/ on your Mac for 30 days. The digest lives on your private claude.ai page. Nothing is sent anywhere else.
Automated reading of X, even in your own logged-in browser, may break X's terms of service, and X could limit your account. The slow pace and safety stops reduce that risk but don't remove it.

Install

curl -fsSL https://raw.githubusercontent.com/vatayush/feed-curator/main/install.sh | bash

It needs macOS, Google Chrome and Claude Code. The installer downloads Feed Curator, registers the helper and the launchd job, asks about automatic curation, and opens Claude Code once to create your page. The one step Chrome doesn't allow from a script is loading the extension: on chrome://extensions, turn on Developer mode and choose Load unpacked.
